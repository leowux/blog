## 导语

Claude Code 新增的跨会话消息功能，允许同一台机器上的独立会话互相发现并发送纯文本消息；通过 Remote Control，其他机器或 Web 会话可回复已收到的消息。它在 8 月 8 日登上 Hacker News 首页，写作时约有 124 分、48 条评论。

这不是把多个 agent 的上下文简单拼在一起。官方明确说明，消息不携带对话历史或文件；接收方会在工具调用之间读取消息，正在执行的工具不会被中断。这个克制的边界很重要：它把并行开发中的“我已经改了什么、你现在被什么阻塞”变成轻量交接，而不是让会话彼此继承难以审计的隐式状态。

## 核心观点

跨会话消息提供两个能力：用 `ListAgents` 发现可达会话，再用 `SendMessage` 传递摘要、状态或决定。适用场景包括：一个 worktree 已完成会影响另一项工作的变更、长时间测试需要回报结果，或一个会话已经回答了另一个会话的阻塞问题。消息只是协作信号；完整上下文仍应通过恢复会话、仓库提交、任务单和可复现命令获得。

这一区分避免了一个常见误区：并行 agent 的主要难题不是“如何让每个 agent 都记住一切”，而是如何让关键信息在恰当的时机、以可验证的形式抵达正确的 owner。把消息限制为文本摘要，会迫使真正的成果继续落在代码、测试结果、变更集和文档上。

## 技术影响

功能的安全模型同样值得关注。接收会话有自己的入站控制：消息可被投递、暂存等待批准，或直接拒绝。另一会话发来的文本不能替用户批准权限、不能修改配置，文本中的命令也不会自动执行；如果后续动作需要权限，接收会话仍会提示。这意味着消息应被视为不可信的协作输入，而不是共享管理员通道。

跨机器的能力也被刻意收窄：本机可发起新消息和回复，远端与 Web 会话只能回复既有消息；本机传递走每个会话的 Unix socket，而不是经由 Anthropic 服务器。功能要求 Claude Code 2.1.224 或更高版本，且目前面向 macOS 与 Linux；云平台、配置和功能标记还可能影响可用性。部署时需要先确认实际会话是否在可达列表中，而不能只依赖版本号。

## 工程启发

1. 用消息传递“指针”，不用它传递事实的唯一副本。每条交接应链接到 commit、worktree、测试命令或任务编号；消息中写清变更、影响范围、下一步和证据位置。
2. 明确消息的信任级别。对无人值守会话，审视 `crossSessionInbound` 的设置；涉及发布、密钥、权限或数据迁移的请求，仍由接收会话的权限策略和人工审批把关。
3. 为并行任务划分文件与决策 owner。消息能降低等待时间，却不能解决两个会话同时改同一文件的冲突。先定义可独立交付的边界，再用消息通知依赖方何时可以 rebase、验证或接手。
4. 记录可观测的收尾信号。长任务结束时发送测试结果、失败原因或已知风险，而不只说“完成了”；这样其他会话才能依据证据继续工作，而不是重新猜测状态。

跨会话消息的价值不在于制造一个无边界的“多 agent 大脑”，而在于为独立执行单元补上一条有权限隔离、可被拒绝的协作通道。对工程团队而言，最可靠的组合仍是：消息负责及时性，版本控制和验证负责真实性，权限系统负责执行边界。
