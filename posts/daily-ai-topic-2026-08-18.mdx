## 导语

今天最值得关注的 AI 技术话题是：GPT-5.6 Sol 价格下调 50%。该消息以 OpenRouter 的模型页为链接登上 Hacker News 热门讨论；截稿时已有 400 余分和 250 余条评论。当前页面列出的标准价为每百万输入 token 2.50 美元、输出 token 15 美元，并给出了 105 万 token 上下文窗口。

这条消息值得讨论，不是因为“更便宜”本身，而是它再次把 Agent 产品的成本边界推到台前：同一个模型名在不同路由、上下文长度、缓存命中率和加速模式下，最终账单可能截然不同。

## 核心观点

价格变化首先应被当作一次部署配置变更，而非一句营销结论。Hacker News 帖子的标题将这次变化概括为 50% 下调；OpenRouter 当前模型页则提供了可核验的现价。它们只能说明该聚合平台上这一模型路由的展示与定价状态，不能自动推导为 OpenAI 在所有 API、云平台或企业合同中的统一降价。

这一边界很重要。OpenAI 的更新日志显示，GPT-5.6 家族的不同变体和模式会分别调整：7 月底公告提到 Luna 与 Terra 的价格下调，并为 Sol 提供按标准价两倍计费的 Fast 模式。也就是说，工程团队若只用一个“模型单价”来估算成本，很容易把路由商价格、官方价格、缓存价和加速价混为一谈。

## 技术影响

对长链路 Agent 而言，输出 token 往往比输入更昂贵，错误重试和工具循环又会进一步放大输出量。以当前展示的价格为例，1,000 万输入 token 与 100 万输出 token 的标价成本约为 40 美元；如果工作流主要生成长篇代码、不断修复再运行，输出侧很快会成为主要支出。这比只看“每百万 token 降了多少”更接近真实预算。

长上下文也不能简单等同于低成本。OpenRouter 页面显示，当输入超过 27.2 万 token 时，Sol 的输入和输出价格会进入更高档位；缓存读取与缓存写入也有独立价格。因此，堆积完整对话、日志和仓库文件来追求一次性解决问题，可能同时提高单次调用成本、延迟和失败重试的代价。

## 工程启发

1. 建立路由级成本基线。记录实际调用的提供商、模型版本、输入输出 token、缓存读写、上下文长度和加速档位；不要只保存一个抽象模型名。
2. 将成本评测接入质量评测。为同一任务集比较成功率、总延迟、工具调用次数和每次成功的成本，而不是仅比较单价或单轮回答质量。
3. 为长任务设置预算护栏。限制最大输出与重试次数，在上下文接近价格分档前主动摘要，并对昂贵的 Fast 模式或备用路由设置可观察、可回滚的开关。

模型价格下调为更多实验留出了空间，但不会替代工程上的成本治理。能持续获益的团队，会把价格表当作动态输入，把可复现的调用遥测和任务级评测当作决策依据。
